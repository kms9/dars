Issue 是 DARS 中安排工作的基本单位：一项功能、一个 bug、一次调研，任何需要智能体或小队负责推进的工作。围绕它的讨论、状态变化和每次执行都留在同一处，无需再从聊天记录或终端日志中拼接上下文。

## Issue 的组成

| 内容 | 用途 |
|---|---|
| **标题和描述** | 目标、背景、要求和验收条件。 |
| **状态** | 工作处于哪个阶段。 |
| **负责人** | 智能体或小队。 |
| **动态和执行日志** | 评论、状态变化、执行任务和智能体返回的结果。 |

![Issue 详情：描述、讨论、右侧属性与执行日志](/images/docs/quickstart-run-result.png)

## 创建 issue

在 **Issues** 页面新建，填写标题与负责人即可，其余属性随时补充。创建请求需要 `Idempotency-Key`。

每个 issue 有一个编号，例如 `MUL-123`。数字在工作区内递增；管理员修改工作区的 issue 前缀后，编号会用新前缀显示。详见[工作区](/workspaces#创建工作区)。

## 选择负责人

| 负责人 | 效果 |
|---|---|
| **智能体** | 为该智能体创建一条执行任务。 |
| **小队** | 由小队 leader 接收，再决定交给谁处理。 |

人类成员可以创建与评论 issue，但不作为负责人。分配给智能体或小队时，issue 进入 `todo` 会立即入队；运行时离线时，任务留在队列中等待。已归档的智能体和小队不能被分配。

分配不会绕过智能体的访问范围（Access）；分配给小队时，校验的是 leader 的 Access。详见[分配 issue 给智能体](/assigning-issues)。

## 状态

| 状态 | 含义 |
|---|---|
| `backlog` | 暂不启动。已分配给智能体的 issue 需离开 `backlog` 后才会创建执行任务。 |
| `todo` | 已明确，等待开始。 |
| `in_progress` | 正在处理。 |
| `in_review` | 已有结果，等待检查。 |
| `done` | 已完成。 |
| `blocked` | 暂时无法继续。 |
| `cancelled` | 不再继续，保留记录。 |

状态之间没有固定流转，成员和智能体都可以直接修改（智能体经 task token 时字段受限）。

把 issue 分配给智能体后，智能体开工时应把状态从 `backlog` / `todo` 推到 `in_progress`，交付后再推到 `in_review`。这些状态变更由智能体在运行中显式写入——task 开始或完成时，服务端不会自动把 issue 标为 `done`。`done` 通常留给人工确认。

<Callout type="info">
一个由系统执行的变化：

- 执行失败，且该 issue 没有其他执行、也没有触发重试时，`in_progress` 回到 `todo`。
</Callout>

## Issue 与执行任务

Issue 是持续存在的工作记录；[执行任务（task）](/tasks)是智能体的一次具体执行。一个 issue 可以先后产生多条执行任务——第一次实现、补充修改、再次检查。执行任务"已完成"只表示这一次执行结束；issue 是否完成，以 issue 的状态为准。

## 删除 issue

任何工作区成员都可以删除 issue。

<Callout type="warning">
删除不可恢复：issue 及其评论和关联记录会被永久移除，尚未结束的执行任务会被取消。不再继续时把状态改为 `cancelled`，讨论和结果仍可查阅。
</Callout>
